# v4.5.0 — Tool Inventory

Released 14 September 2026.

The largest release so far, and the first one to carry **Tool Inventory** — a new tool that replaces the manual quarterly tool inventory spreadsheet, 48 tabs of it going back to 2014. Alongside it: two Pax8 Sync fixes that were quietly destroying data, and a Company Mapping screen that now knows about every platform rather than a hardcoded five.

## Tool Inventory

**What it answers:** for each client, how many seats, devices and users is ANS actually providing on each vendor platform — and how does that compare to what the client is contracted for?

It shows those two numbers side by side and stops there. There is **no verdict, no severity, and no dollar figure** anywhere on the screen, by design. You judge the difference.

### Eight platforms counted, two indicators

| Platform | Counts |
|---|---|
| Datto RMM | devices |
| RMM DT&LT | devices — how many of that same Datto RMM total are desktops and laptops |
| RMM Servers, Workstations | devices — a second breakdown of the same total: every countable RMM device that isn't network gear |
| Duo Security | users |
| Datto SaaS Protection | users |
| BitDefender | devices |
| Cyrisma | devices |
| CyberQP Elevate | users — enabled end-user accounts |

Plus two Yes/No licensing indicators: **Liongard** and **Lifecycle Manager X** (the same indicator previously labelled LifeCycle Insights — renamed to name the product it actually reads; the historical quarterly tabs still use the old name).

**Splashtop Pro** has a column but it is always empty, and it is now the only one. Splashtop exposes no vendor API at all, so it needs a manual import — that's its own future phase, and the column is deliberately blank rather than silently zero.

### Frozen monthly snapshots

Counts are read from a **snapshot of a month**, not live every time you open the tool. A snapshot is taken automatically on the 1st of each month for the month just closed, or on demand with **Take Snapshot Now**.

A month already taken keeps the reading it was taken with — that is the point. Any granted user can take a month's first snapshot; **replacing** an existing month needs the Hub admin role, and the replaced snapshot is kept for audit.

### It tells you what it doesn't know

A count that couldn't be established is never quietly shown as zero. Cells distinguish between:

- **No account** — the vendor genuinely lists nothing for this client.
- **Not in this snapshot** — a column added to the report after that month was frozen.
- **Unconfirmed** — shown in place of *No account* on any platform that still has a vendor account not yet mapped to an Autotask company, because the report can't yet rule out that unmapped account being this client's. It clears on that platform's next snapshot, once every account is mapped.

And three supporting lists keep three different problems apart instead of collapsing them into one number: clients with **no MSC record at all** (a real finding), **vendor accounts matching no Autotask company** (a mapping to-do, not a client), and clients whose **MSC baseline simply couldn't be read** this snapshot (unknown, never zero).

### Fixing a mapping without leaving the tool

An unmapped vendor account can now be mapped to a client **from the tab that lists it** — one row at a time or several at once. The client picker searches the Hub directory by name or Autotask ID, with **exact matching only, never a guess**: a wrong auto-match would misattribute one client's licence count to another, which is worse than asking a person. Snapshot diagnostics gained the same action for Liongard and Lifecycle Manager X.

Every confirmation says which month the mapping first applies to — always the **next** snapshot, never the frozen one on screen — and names any existing mapping it would replace.

### Inactive clients

The nightly identity sync now refreshes each company's active/inactive status from Autotask in its own read-only pass. A client Autotask marks inactive **leaves every tab**, the client detail, the tab counts, the totals and the export.

They are still *read*, deliberately — and an inactive client still carrying a non-zero count on any platform raises an **alert in the app and a Teams message**, naming the client, its Autotask ID and the per-platform counts. That is licence spend on someone who is no longer a client.

This is the part of the tool that has never run on anyone's installed app before now. A one-off catch-up was run by hand on 14 September, which flipped 36 companies to inactive — but nothing kept that current until this release. From here it maintains itself nightly.

### Two counts that come with caveats

Most of these numbers were checked against the hand-kept quarterly tabs before being trusted. Two could not be, and the tool says so rather than implying a confidence it doesn't have:

- **Cyrisma** has never appeared in those tabs, so there is no answer key. The figure rests on Cyrisma's own reporting until someone spot-checks it against the portal.
- **CyberQP Elevate** was checked and **failed** — the closest variant sat about 12% high. So the column reports enabled end-user accounts, something defined and reproducible, and states plainly what it is. It deliberately does **not** match the CyberQP invoice, which bills a round committed block rather than a measurement, nor the portal's agent count, which the API cannot expose at all.

Also included: per-client and per-vendor-account **exclusions**, and a full **Excel export** matching the existing Anchor Tool Inventory workbook's layout.

## Pax8 Sync — two fixes that were destroying data

Both were found by driving the real handler against a 254-company capture of the live directory, and both had been silently losing data on every sync.

**Non-Pax8 platform mappings were being destroyed.** The Pax8 full sync rebuilds every directory entry from scratch, and it copied forward only three hardcoded platform names. Anything else was wiped org-wide on the next sync — measured at **63 companies losing at least one platform mapping**, including 61 companies' Meraki mappings and 20 companies' Duo mappings. Now zero.

**Company metadata was being wiped, and companies were being deleted.** The same rebuild dropped every metadata field it didn't explicitly name — MSC name, CIPP domain, classification, SharePoint folder, project/task links, Block Hour recipients and more — overwriting them with nulls. Separately, a company that owned no platform rows was left out of the payload entirely, and the directory treats the payload as authoritative, so it was **deleted**. Since exclusions default to off, a deleted company that is still an active customer in Autotask came back **un-excluded** on the next identity sync — and 101 of the affected companies had been excluded by hand. Both are fixed.

## Company Mapping — every platform, not five

Company Mapping's platform columns are now rendered from one declared **portal registry** rather than a hardcoded list of five, showing nine columns. That registry also opened a mapping write path for four platforms that previously had none: **Duo Security, BitDefender, Liongard and Lifecycle Manager X**.

Pax8 is shown read-only (its rows are written by its own sync), and Datto RMM is deliberately absent — it matches on the Autotask ID held inside Datto, so mapping it by name would silently never take effect.

## Inventory Reports — a snapshot fix

Taking a month's snapshot twice in one session could fail on a database constraint with an error that pointed at the wrong thing entirely — most likely when replacing a month straight after taking it. Nothing was ever corrupted (the whole operation rolls back), but the error sent you looking in the wrong place. Fixed.

## Upgrading

The app updates itself. This release needs the `phase54`, `phase55` and `phase56` database migrations applied, and the Tool Inventory tool granted to the roles that should see it (Admin, Finance and Strategic are the intended ones) in **Access Management**.
