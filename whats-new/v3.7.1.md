# v3.7.1 — Block Hour Client Report fixes

## Fixed

A bug-fix batch for the **Block Hour Client Report**, found during AM spot-checking of the v3.7.0 release.

**Unposted-time metric was badly inflated.** The dashboard's internal-only "unposted time pending approval" figure summed a time entry field (`hoursToBill`) that turns out to never clear once an entry is actually posted — one client showed 29.0 "pending" hours when only 0.5 hours (2 entries) were genuinely still awaiting approval. This figure is now checked against Autotask's own billing records directly, so it only counts time that hasn't actually been posted yet. Non-billable time is also excluded, since it never draws against a block's hours regardless of approval status.

**"Tickets this period" list looked padded.** A recurring same-titled ticket — a weekly comanaged meeting, for example — posted one near-identical line per occurrence. These now group into a single line with an occurrence count (e.g. "Weekly comanaged meeting (×4)") and combined hours.

**"Hours match Autotask" guardrail had false failures.** The AI-drafted client narrative is allowed to cite an individual ticket's hours for color (e.g. "14.5 hours went toward QuickBooks access"), but the guardrail only recognized the three summary totals (purchased/used/remaining) as valid — so a narrative correctly quoting a real number could still fail the check. Individual ticket hours now count as valid too.

**Editing the narrative didn't update the guardrail.** A coding error meant the live guardrail recheck silently failed every time an AM typed in the narrative box, so the pass/fail indicators and the Approve button stayed frozen at whatever they showed when the report was first generated — no matter what was edited. This is now fixed; the guardrails and Approve button update live as you edit.
