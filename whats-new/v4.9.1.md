# v4.9.1 — User Audit: safer Generate and a truer AM Dashboard

Released 8 October 2026.

A batch of User Audit Report fixes, all from Gary Bennett's reports.

## Overdue clients stay Overdue when you re-run them

Running an audit on an **Overdue** client (a report was sent and never came back) used to bounce the client straight into **Needs an audit run**, as if nothing had ever been sent. It now stays under Overdue until you actually email the new report.

## Regenerating a report no longer erases a send

If you generate and send a report, then generate a fresh one without sending it, the AM Dashboard used to forget the send. Now a client stays in the cycle of the report you last *sent*, with its original Sent and Return By dates. A small line under the client's name tells you a newer report exists:

- **Newer report generated <date>, not sent** when an earlier report is still out with the client.
- **Report generated <date>, not sent yet** when nothing has been sent.

Once you send the newer report, it becomes the client's cycle and the line goes away.

## The AM Dashboard refreshes itself

After a Generate or a Send, the dashboard updates on its own. No more leaving and coming back to see the change.

## Generate tab

- **Create Autotask CRM note** is ticked by default.
- Every visit starts with nothing ticked, so pressing **Run Audit** for one client can no longer carry a previous client's tick into the next run.
- Email is only offered when exactly one client was run. Tick two or more and there's no email field or Send button.

## Write-back warns about a newer, unsent report

If you open Write-back for a client whose newest report in SharePoint was generated *after* the one you sent, an amber warning says so. The file it loaded may not be the copy the client returned, so check the file name shown or upload the client's returned copy instead.
