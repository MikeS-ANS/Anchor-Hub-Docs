# v4.6.4 — User Audit Report: a sent report reads as sent

Released 21 September 2026.

Reported by **Gary Bennett**. A User Audit report that had already been emailed to a client stayed sitting under **Needs an audit run**, and nothing about the send reached the client's Autotask record. The practical cost: one client was audited three times and emailed to two different contacts in two days, because the dashboard kept saying it still needed a run.

Everything below is in **User Audit Report**. Nothing else in the Hub changed.

---

## The Account Manager Dashboard

**A report that's out with the client now sorts under "Sent, not returned" — never under "Needs an audit run".** Each client appears in exactly one section. The action that moves an in-flight report forward is chasing the client or doing the write-back, not running the audit again, so that's where it now lives.

**A client can be waiting on a return *and* overdue on its cohort schedule at the same time.** It's still listed once, but it carries the schedule fact with it — a small grey **audit due since &lt;date&gt;** line under the client's name, or **audit due — no cohort assigned** for a client the schedule doesn't cover yet. Nothing is hidden; it just isn't listed twice.

**Overdue rows gained a "Run Audit" button** alongside Start Write-Back, for a client who's gone dark and whose cycle you want to deliberately restart.

> **One thing that looks like a bug and isn't.** Re-running an audit mid-cycle moves the client back to "Needs an audit run" until the new report is emailed. That's correct — the report now on file genuinely hasn't been sent — but it's worth knowing before it surprises you.

## The History tab

A new **Sent** column shows the date the report was emailed. Hover it to see every send tied to that run, each with its own date and the exact recipients — a report re-sent to a second contact at the client shows both. A dash means the report was generated but never sent, which is itself worth noticing.

## The Autotask account note

**The two notes now have distinct titles** — `User Audit — Report Generated — <Month Year>` and `User Audit — Write-Back — <Month Year>`. They previously shared one identical title, so a client's account showed two indistinguishable notes per cycle and you had to open each one to tell which was which.

**Sending now records itself on that note.** If you created the CRM note for the run and hold a personal Autotask key, the title becomes `— Report Generated & Sent —` and a line is added naming the date and every recipient — so the account itself shows whether the report went out, and to whom. This happens after the email has already gone, so a problem here never fails the send; if it can't be confirmed you'll see a small **⚠ account note not updated** next to the send confirmation.

## Also fixed

- **Two separate ways the same report could reach a client twice.** The Send button stayed active through the slower post-send work with no duplicate guard; and separately, a failure writing the activity-log row reported a successfully delivered email as failed, inviting a re-send.
- **Three User Audit filters held a client's name across sign-out**, so the next person to sign in on the same machine could land on a list silently filtered to someone else's client.

## Known limitation

If Microsoft accepts the message but the confirmation is lost in transit, the app still reports an error for an email that was actually delivered. Check the client's History row before re-sending.
