# v3.7.2 — Block Hour Client Report: Regenerate + monthly hours-used fix

## Fixed

**Regenerate could leave a report showing stale, wrong numbers.** Clicking Regenerate on a queued report only asked the AI to write a fresh pair of narratives over the numbers the report already had stored — it never re-checked Autotask. For a monthly report (a genuinely closed prior month) that's harmless, but an ad hoc, block-scoped report's window runs through *today* for a still-open block, so real usage can keep accruing after the report was first generated. Found live: an ad hoc report for a client's Block Hour contract claimed the block was 100% used with zero hours remaining, when Autotask showed less than half the block had actually been used. Regenerate now re-pulls live Autotask data for both ad hoc and monthly reports before writing the narrative, and saves the refreshed numbers — not just the reworded text.

**Monthly report's "hours used this period" wasn't actually scoped to the period.** It was always the block's entire usage total since it was purchased, not that specific month's billed work — so every monthly client email was quietly reporting the block's lifetime total dressed up as a monthly figure. It now sums the actual work billed in that calendar month. "Hours remaining" is unchanged — that's a live property of the block itself, not something tied to a specific month, so pairing this month's usage with the block's current remaining balance is the combination that's actually useful to a client.

## Improved

**Can regenerate a monthly report for a client who already has one this period.** The "Generate now" picker previously hid a client from the list the moment *any* report existed for the current period, no matter its state — so there was no way to run a fresh one mid-month, or to reconsider after skipping. Now, a client reappears in the picker once their existing report for that period is **sent** or **skipped**; only a still-open (pending/approved) report blocks a repeat generate.
