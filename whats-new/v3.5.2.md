# v3.5.2 — Strety widget: Connect button now shows on any reconnect signal

Follow-up patch to the v3.5.1 Strety widget fix.

## Fix

v3.5.1 fixed the refresh-token race itself, but its self-heal step — clearing the dead token from Azure Key Vault so the widget would fall back to the "Connect Strety" prompt — silently fails for any user who doesn't have Key Vault write permission. That's most non-admin users. For them, a dead token left the widget stuck showing "Strety unavailable" with no way back to Connect, exactly like before v3.5.1 shipped.

Now the widget doesn't wait on that Key Vault clear at all. It trusts the `needsReconnect` signal directly and shows the Connect button regardless of whether the Key Vault clear succeeded or failed. Both the "never connected" and "connection went dead" paths render through one shared `_renderStretyConnectStrip()` helper in `app.js`, so they can't drift out of sync with each other again.

No user action needed — if your widget was stuck on "Strety unavailable," it should now offer the Connect prompt on next load.

**Still open, not fixed by this patch:** whether non-admin users should get Key Vault write access to the Strety refresh-token secret, or whether token refresh should be centralized into an admin-only process instead. That's a deliberate architectural call still pending — this patch just makes sure the *symptom* (no way back to Connect) can't recur while that's decided.

See [Roadmap](../getting-started/roadmap.md) for where this sits alongside the v3.5.0 widget and v3.5.1 patch it follows.
