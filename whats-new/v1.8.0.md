# v1.8.0 — Meraki License & EoL Expiration Report

## New Tool: Meraki License & EoL Expiration Report

This release adds a new tool that scans all Meraki client organizations for expiring licenses and hardware approaching end-of-life, then lets you act on them — sync Autotask records, create renewal tickets, and track everything without leaving the Hub.

---

### License & EoL Scanning

The scan checks every device across all mapped Meraki orgs and classifies each one by urgency: **Expired**, **Critical**, **Warning**, **Notice**, **EoS** (end-of-support), or **CO-TERM** (co-term licensing model). Results are grouped by client org and shared across all Hub users via a shared SharePoint cache — Gary scans at 8am, Shawn sees results immediately.

---

### Filtering & Search

- Filter by severity badge (Expired / Critical / Warning / Notice / EoS / Dormant / Alerting)
- Click a badge once to **include** (green), click again to **exclude** (red) — multiple filters stack
- Real-time search across device name, serial, model, and org name
- **Export CSV** of the current filtered view

---

### Autotask Integration

Devices with Autotask Configuration Items get a date comparison. When the AT warranty/expiry date differs from the Meraki license date by more than 1 day, a **Sync** button appears — click it to update the AT CI in one step.

**Tickets** are created in the correct AT queue with work type, SLA, source, and priority resolved automatically at runtime (no hardcoded IDs). The tool checks for an existing open renewal ticket before creating a new one to avoid duplicates.

**Time entries** default to the logged-in Hub user — no manual resource selection needed.

---

### Batch Ticket Creation

Enable **Batch** mode, select multiple orgs, and click **Create Tickets** to create renewal tickets for all of them in one operation. Each org gets its own ticket. Orgs without an AT company match or with no qualifying devices are skipped with a clear message.

---

### Exclusions

Exclude individual devices, hardware models (e.g. MT sensors), or entire orgs from the report. Exclusions are per-company and shared across all Hub users. A global model exclusion list covers hardware that should be skipped everywhere.

---

### Scheduled Scans

Configure automatic daily or weekly scans in Settings. Scans run in the background with desktop notifications. If the Hub was closed during the scheduled window, the scan fires automatically on the next launch (without triggering on every first launch).

---

### Other Fixes in v1.8.0

- **AT DateTime error on co-term sync** — Meraki returns dates in "Dec 15, 2026 UTC" format which Autotask rejected. Dates are now normalized to ISO format before any AT write.
- **AT role error on time entries** — Time entries now use the resource's actual default role from Autotask instead of a hardcoded name, fixing the "AssignedResourceID and AssignedRoleID combination not defined" error.
- **ANS org missing from scan** — Anchor Network Solutions was incorrectly filtered out of Expiration scan results. Fixed.
- **Batch ticket button silent failure** — The Create Tickets button now shows a clear message when no orgs qualify under the current filters instead of doing nothing.
- **Stale batch selections after filter change** — Batch selections are now cleared when switching filters, preventing invisible orgs from being included in ticket creation.
