# v4.6.1 — Project Portfolio: Completed Projects, Billing & Revenue

Released 18 September 2026.

Seven improvements to **Project Portfolio** — the screen that replaced Professional Services' hand-kept Planner board for tracking every open client project — plus two numbers on the board that were quietly wrong and are now fixed. All of this came out of Andi Gingerich using the tool day to day and flagging what didn't hold up.

## Completed projects, properly

Project Portfolio now has three views instead of one: **Open**, **Completed**, and **All**. The "Completed within" time window now applies to Completed and All as well, and if you pick a window that reaches further back than the tool actually has data for, it tells you so instead of just showing you an empty list.

Completed projects are also kept for good now. Before this release, a project quietly dropped off the board once it aged out of the sync window — so the further back you asked to look, the less complete the answer got. Now nothing is ever removed just because time has passed, which is what makes Completed and All actually useful for asking "how many projects wrapped up last quarter."

## The grid scrolls — the page doesn't

Column headers now stay pinned at the top of the grid as you scroll down a long list, and status text that used to stretch a row tall is clipped to a few lines with the full text available on hover. On a long list, the scrollbar is where you're actually looking instead of trailing off below the bottom row.

## Opening a project keeps your place

Opening a project's detail panel, editing something, and having the panel jump back to the top used to be the norm. Now it only resets to the top when you open a genuinely different project — editing in place keeps your scroll position.

## A Billing column

Every project now shows **Fixed fee**, **T&M**, **Not tagged**, or a dash. This reads from the contract's name rather than Autotask's own contract type field, because every project contract at ANS is set up as Fixed Price in Autotask regardless of how the work is actually billed — so the contract type field would be actively misleading here. **Not tagged** is the one worth paying attention to: it means a real project contract whose name never got a billing suffix added, and the matching filter pulls up exactly that cleanup list.

## Estimated revenue — and a number that was badly wrong

Every project also now shows an estimated revenue figure, pulled from the contract, with a filter and a running total for whatever's currently on screen.

Here's the important part: it only ever reflects a project's **own** contract. Most open projects aren't billed that way — they sit on a client-level agreement instead (Recurring IT Services, Block Hours, T&M Support), and that contract's dollar figure is what the client pays for everything, typically for a year, not what this one project is worth. Before this was caught, the portfolio's revenue total was pulling those client-level figures in anyway, and it overstated the real open-project revenue by roughly **25 times** — about $3.45 million shown against a real figure closer to $137,000. That's fixed: revenue and billing type only ever come from a project's own dedicated contract now, everything else reads as a dash, and hovering the cell tells you exactly why.

## Open a project's SharePoint folder from the panel

The detail panel has a new **Open project folder** button. When a project's own subfolder can exist, it opens that folder directly; otherwise it falls back to the client's overall Projects folder and says so, and it never guesses at a client folder it can't actually identify.

## Your filters stick around

Every filter — scope, department, phase, lead, billing type, the completed window and date range, and sort order — is now remembered per person, per machine, the next time you open the tool. Search is the one deliberate exception, since a saved search term is more often stale than useful.

## The other number that was wrong

Beyond the revenue figure above, the Completed count itself was measuring the wrong date. It had been going by a project's originally *planned* finish date rather than when it actually wrapped up — those two dates differ by more than a month on roughly half of ANS's completed projects. Last quarter's completed-project count read as **24**; the real figure, measured the right way, is **105**. Completed and All now both key off the date a project actually finished.
