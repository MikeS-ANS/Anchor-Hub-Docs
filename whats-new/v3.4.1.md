# v3.4.1 — Kaseya Invoice Processor billing fixes + SharePoint upload

## New

**Drag-and-drop invoice upload** — both the Kaseya and BlackPoint invoice processors now let you drag an invoice file straight onto the app (or click to browse) to upload it into the correct SharePoint folder, instead of having to upload it there yourself first. The newly uploaded file is automatically selected and ready to process.

## Billing accuracy fixes

A cluster of real billing-correctness issues in the Kaseya Invoice Processor's bundle handling and Autotask push, found while testing the tool against live data:

- **Bundle-override matching** — the Workplace bundle override settings only matched a client if you typed its exact legal name (punctuation, "Inc"/"LLC" and all). Now normalizes both sides so typed overrides actually apply.
- **SaaS bundled-flag saves** — checking multiple SaaS bundle boxes in quick succession used to race (each click saved independently) and could silently lose earlier changes. Saves now batch into a single round trip via a "Save Changes" button.
- **SaaS platform targeting** — the SaaS Protection push used to try attaching *both* the GSuite and Microsoft 365 backup services to every client, creating a bogus duplicate line on whichever platform a client doesn't actually use. Now targets only the one matching the client's real platform (from the Company Directory's GWS/M365 flag).
- **Multi-domain clients** — Kaseya bills a client's separate domains as distinct line items even when they're all one Autotask company. These are now aggregated correctly before computing bundle amounts and before pushing — previously the bundle allowance was double-counted per domain, and the push itself silently overwrote earlier domains' contributions instead of summing them.
- **Contract selection** — when a company already has next year's contract provisioned early, the push now correctly targets whichever contract's date range covers *today*, instead of always picking whichever contract starts latest.
- **First-time service attachment** — pushing a brand-new service line (a client's first month on a given product) now goes through the correct Autotask endpoint; the previous one had no working create path in this Autotask API version and always failed.

## Also in this release

- A live current → new quantity preview now shows before every Autotask push, opening immediately with a loading indicator instead of leaving the button looking unresponsive while it fetches.
- "Last pushed" timestamps now show under the push buttons in both the Kaseya and Pax8 invoice processors.
- A dismissible warning banner now surfaces MSC/Revenue workbook load failures that previously failed silently.
- AT lookups during preview/push are now parallelized, noticeably speeding up pushes on large invoices.
