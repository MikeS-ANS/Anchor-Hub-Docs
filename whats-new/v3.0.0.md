# v3.0.0 — Azure Backend Migration

The biggest infrastructure change since the Hub launched: shared application data has moved off SharePoint files and onto a real backend — Azure SQL, accessed through a dedicated Azure Functions API, with centrally-managed settings in Azure App Configuration. This release also folds in v2.7.0 and v2.8.0, which laid the groundwork.

## Why this matters

The Hub's shared data — the Company Directory, per-tool run history, and centrally-managed settings — used to live in JSON files on SharePoint, read and rewritten wholesale by whichever machine happened to run a tool. That worked, but it doesn't scale the way a real database does: two people saving at once could race each other, there was no record of who changed what, and "centrally managed" settings could only actually be changed by editing a file directly.

None of that changes how you use the Hub day to day — every tool works exactly the same. What changes is what's underneath:

- **A real database.** The Company Directory, Project Analysis/Project Time Summary/Kaseya/Blackpoint run history and snapshots, and User Audit history all live in Azure SQL now, accessed through a dedicated API layer instead of shared files.
- **Every request is authenticated as you.** The backend validates your own signed-in Microsoft 365 identity on every single call — it never trusts a client to say who it is.
- **A real audit trail.** Every write goes through a shared activity log, so "who changed this and when" is always answerable — not just for admin actions, but woven through the whole backend.
- **Settings you can actually change from the app.** Profitability, Renewals, Kaseya cost-split, Prompt Templates, Margin Analyzer, Meraki's expiration threshold, and User Audit settings used to show "contact Mike to change this" — now a Hub Admin can edit them directly from each tool's Settings panel, and the change is enforced and audited server-side, not just hidden behind a UI toggle.
- **Live monitoring.** Application Insights is wired up, so backend health and performance are visible in real time rather than inferred from user reports.

## What you'll notice

Nothing, mostly — that's the point. Shared data updates instantly across everyone's Hub instead of waiting on a file sync. If you're a Hub Admin, you'll notice several Settings panels that used to reject your changes now actually save them.

## v2.7.0 / v2.8.0 (folded into this release)

- Repo-privacy groundwork: tenant-specific configuration extracted out of source, auto-updater made aware of the now-private GitHub repo.
- A SharePoint installer mirror for installing the Hub on a personal or unmanaged device without GitHub access.
- Minor fixes: the "Open Project" button now only links genuinely-open Client Time Tracking projects, and a new button creates one directly from Company Directory.
