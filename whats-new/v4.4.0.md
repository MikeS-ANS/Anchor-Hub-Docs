# v4.4.0 — User Audit Report: Bi-Monthly Cohort Scheduling

Released 8 September 2026.

One change to User Audit Report, replacing how the tool decides when a client is due for an audit.

## Bi-monthly cohort scheduling

Every client used to become "due" on a flat rolling 60-day clock from its last audit. That's gone, replaced with a predictable calendar: every client now sits in either the **Odd** cohort (audited January, March, May, July, September, November) or the **Even** cohort (February, April, June, August, October, December), so each client is audited every other month on a fixed schedule instead of a rolling day count.

- **Cohorts are sticky.** Reassigning a client to a different account manager never changes its cohort.
- Each account manager's book is split so the two halves — Odd and Even — stay close in both client count and total included users, so neither month is lopsided.
- A cycle only counts as **done** once the report was generated *and* the client's write-back was applied. A missed cycle doesn't reset — it carries forward, with "days overdue" measured from the *original* due date, so a client missed for several cycles in a row reads as increasingly overdue rather than quietly resetting every other month.

**New Cohorts tab** (same access as the AM Dashboard) shows two columns per account manager — Odd and Even — with running client-count and included-user totals, and a per-client button to move it to the other cohort by hand.

- **Generate initial split** — the one-time, per-AM migration onto the new schedule. It's deliberately recency-aware: the more-overdue half of the roster (weighted by included users, not just headcount) lands in whichever cohort is due *this* month, and the recently-audited half waits for next month — so turning this on doesn't immediately re-audit a client that was just audited a few days earlier.
- **Rebalance** — a separate, on-demand, balance-only action for a roster already migrated. It refuses to run for an account manager who hasn't been through the initial split yet, so it can't be used to bypass the recency-aware logic above.

Both actions preview every proposed move before anything saves. A brand-new client with no cohort yet auto-assigns to whichever cohort is currently lighter for its account manager — once that AM has already run the initial split.

The AM Dashboard's **Needs an audit run** list is now driven by each client's cohort due date instead of a day count, with a colored **ODD**/**EVEN** badge and a **Due Since** column replacing the old "Days Since" figure.
