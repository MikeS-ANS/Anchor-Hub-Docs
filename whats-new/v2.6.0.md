# v2.6.0 — Project Analysis Change Orders & Fixes

Two GitHub issues on Project Analysis, plus fixes and follow-ups that came out of testing them.

## New features

**Change order support**
The scope-document picker now supports multiple PDFs at once — select several, or click "Upload PDF(s)" again to add more. The first is treated as the Scope of Work and each additional file as Change Order 1, 2, etc. Drag the ⠿ handle on any attached file to reorder if a multi-select didn't come back in the order you expected. The AI prompt now explicitly treats change orders as extending the original scope baseline instead of judging the project as under-scoped for work a change order already covered.

**Open Project button**
The report header now has an "Open Project ↗" button that opens the project directly in Autotask's web UI. No extra API call — the URL is derived from the project ID and Autotask zone already resolved during the fetch.

## Fixes

**Task phase display**
The same task name can appear under multiple phases on a project, with no way to tell them apart. Tasks now show their phase as a sub-line under the title in both the By Task chart and the Task breakdown table.

**Billing type detection**
Real Autotask contract names use "- FF" and "- T&M" (a space before the code, and an ampersand in T&M), not the tight "-FF"/"-TM" format the v2.4.0 detection regex expected — so every real contract was falling through to the "inferred, verify" fallback. Fixed to match the actual naming convention.

**Report header hierarchy**
The client name line was rendering too close in size/weight to the project title; increased the contrast between them.
