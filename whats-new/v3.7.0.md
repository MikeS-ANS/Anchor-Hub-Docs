# v3.7.0 — Block Hour Client Report

## New

**Block Hour Client Report** — an Account Manager-facing dashboard and AI-narrative review tool for Block Hour clients (Autotask contracts where a client prepays for a fixed block of support hours instead of a flat monthly retainer). Unlike Client Touch Aging, this reads Autotask **live** on every dashboard load rather than through a daily sync — the Block Hour population is small enough that a live read stays well within Autotask's rate limits.

- **Dashboard** — every Block Hour client with hours purchased/used/remaining, a segmented usage bar (handles multiple concurrent blocks per client), block expiration date, Account Manager, search + AM filter, and Autotask deep-links. A calm sky-blue **dormant** flag (not red) marks clients with zero current block coverage — a genuine coverage gap, distinct from the amber "running low" warning
- **Review queue** — an AM reviews an AI-drafted (Hatz.ai) monthly report before it emails the client: hard Autotask numbers shown read-only, an editable client-facing narrative (positive tone, hours-only, never dollar figures), and a separate internal-only narrative. Two guardrails — no dollar figures, and hours matching Autotask — must both pass before **Approve & send**, which emails the client via Microsoft Graph from the signed-in AM's own mailbox; no bulk approve/send
- **Send history** logs every sent/skipped report
- **Settings** — generation schedule, dormant grace period, low-block warning threshold, Hatz.ai model, and a per-client recipients/pause table open to **any** Hub user, not just admins

Marked **Beta** in the sidebar, sitting below Client Touch Aging.

## Also in this release — follow-up improvements

Built in the same cycle, beyond the original spec:

- **Per-block hourly rate** shown in the expandable per-client block breakdown
- **Trailing 12-month average usage + estimated runway** — a rough "hours remaining ÷ recent monthly pace" estimate, loaded on demand per client
- **Unposted-time early-warning** (internal-only) — a heads-up when a client has recent time entered but not yet approved/posted, since that time isn't reflected in the official hours-used figure yet
- **Trailing 12-month spend** column on the main dashboard table
- **On-demand, block-scoped ad hoc report** — from a client's expanded detail row, an AM can pick one or more specific blocks (active or expired) and generate a report scoped to just that block's own date range, through the same AI/guardrail/review pipeline as the monthly report — useful when a client asks what a particular block was spent on
- **Pending-review count badge** on the Review queue tab and in the dashboard's metric strip
- **Activity-log audit trail** for every per-client recipient/pause change made in Settings
