# v3.8.1 — Timesheet Review: Automatic Refresh

**Released:** August 2026

## What's New

### Timesheet Review no longer needs a manual Refresh

Until now, the Timesheet Review tool never updated itself. Someone had to click **↻ Refresh** — and until they did, the tool would show cached data of any age with nothing on screen to suggest it was out of date. You could open the tool, see numbers that looked current, and act on figures that were days old.

Two things now keep it current.

**Background refresh when you open the tool**

Cached data still appears instantly — that hasn't changed, and it's the whole reason the cache exists. But if that data is older than a set threshold *and* the period is still recent enough to be worth updating, the tool quietly re-scans behind what you're already looking at and updates in place.

- The header shows `· refreshing…` while it's working, then clears on its own
- If it can't refresh, the header shows `· refresh failed` and **the data you already had stays on screen** — nothing is blanked out or lost
- The **↻ Refresh** button still works exactly as it always has, for when you want to force a pull
- A period that ended more than the grace window ago is treated as settled and won't be re-scanned, however old its cached copy is — so paging back through past weeks doesn't kick off pointless work

**A once-daily scan**

Once a day, Anchor Hub refreshes the **current week, previous week, current month, and previous month** for every active employee. Most of the time the data is already current before anyone opens the tool.

Two things are worth understanding about this one, because they explain what you'll actually see:

- It runs **only on Hub Admin machines.** The results go into a shared database that everyone reads, so one admin's scan serves every manager — there's no need for it to run on all 35 copies of the app.
- It runs **only while Anchor Hub is actually open.** There's no server that does this on its own. If nobody with admin access has had the Hub open, the background refresh above picks up the slack the next time anyone opens the tool.

### New settings

Under **Timesheet Review → ⚙ Settings → Automatic Refresh**. Like the tool's other settings, these are centrally managed — Hub Admins can change them, everyone else sees the current values.

| Setting | Default | What it does |
| --- | --- | --- |
| **Daily scan** | Enabled | Master on/off switch for the daily scan |
| **Daily scan time (Denver)** | 05:00 | When the scan is scheduled. In practice it runs on the first launch *after* this time, since nobody has the Hub open at 5am — this is expected, not a fault |
| **Refresh on open when data is older than** | 12 hours | How stale cached data has to be before opening the tool triggers a background refresh |
| **Keep refreshing a period for this many days after it ends** | 14 days | Exists because people log time late. Past this, a period is treated as finished and stops being re-scanned |

If you raise the "refresh on open" threshold to reduce background activity, bear in mind it also controls how current the data is when you open the tool. And lowering the grace window means recently-closed periods stop picking up late-entered time.

### Worth knowing

- **The AI features are never triggered automatically.** AI Note Review, Ask AI, and the Review with AI buttons stay click-only, because each one is billed per use. Neither the daily scan nor the background refresh will ever call them.
- Behind the scenes, the date logic that decides where a week or month begins now lives in one shared place, so the daily scan and the period picker on screen can't drift apart and disagree about which week is "this week."

### Nothing changed about

- How timesheet data is classified, flagged, or scored
- The client-facing percentage, the flags, or the CONCERN/WATCH/NORMAL tiers
- Marking a timesheet reviewed, or the deep link out to Autotask for the actual approval
