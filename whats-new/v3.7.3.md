# v3.7.3 — Block Hour Report: monthly work-items date scoping fix

## Fixed

**Monthly report's work-items list could show zero hours even with real work that month.** The underlying query scoped billing items by `postedDate` — when a billing item was administratively approved/posted in Autotask — instead of `itemDate`, when the work itself is actually dated. Posting regularly lags the real work by weeks, so a report generated shortly after month-end could find nothing for that month even when real work happened, simply because it hadn't been posted yet. Found live minutes after v3.7.2 shipped: a client's July report showed 0 hours used, because that month's billing items didn't post in Autotask until August 3rd. Now filters on `itemDate` instead, for both the monthly and ad hoc report paths.
