# v3.7.4 — Meraki Admin Management: access-control fix + audit/bulk-op reliability

## Fixed

**Access control now driven entirely by the Hub Role Matrix.** Meraki Admin Management's own internal access check was still hardcoded to the retired **hub.admin**/**hub.it** roles from before the 9-role migration — since `hub.it` no longer exists, only the literal `hub.admin` role could actually open or use the tool, regardless of what the Hub Role Matrix SharePoint list said. Now reads the same allowed-tools lookup the sidebar already uses, so a SharePoint list change alone is enough going forward — no code deploy needed. This also surfaced and fixed a related gap: the shared role-matrix cache was never cleared on sign-out, so a second person signing in on the same running instance would have inherited the first person's cached permissions.

**Audit scan reliability.** The Audit tab was silently miscounting rate-limited/network-failed orgs as real findings — a failed org looked like it was missing every baseline admin, and in the more serious case, if the baseline "Organization Template" org itself failed to fetch, every other org's real ANS admins looked like "extra," sitting right next to a live bulk-remove button. Fixed with dedicated failure tracking that's never mixed into real data, one retry with backoff for transient errors, and a new **Retry Failed** button that only re-fetches the orgs that actually failed instead of a full re-scan.

**Bulk operations.** The same reliability treatment was applied to **Add to All Client Orgs** / **Remove from All Client Orgs**, and to **Fix All Missing** / **Add All Missing**, which had an even quieter version of the same bug — failed adds were dropped with zero indication at all. All three now show exactly which org/email failed and why, instead of a silent undercount.
