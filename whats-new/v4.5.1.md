# v4.5.1 — Security patch

Released 14 September 2026.

A maintenance release. **Nothing in Anchor Hub looks or works differently** — there are no new features, no changed screens, and no settings to revisit. This release exists purely to update third-party code libraries that Anchor Hub is built on.

You do not need to do anything. The update installs itself the same way every other release does.

## Why this release exists

Anchor Hub, like virtually all modern software, is assembled partly from open-source libraries maintained by other people. When a security flaw is found in one of those libraries, it is published publicly and the fix is to move to a newer version.

GitHub tracks these automatically and had flagged 74 outstanding advisories against the project. This release clears **37 of them, including the only one rated critical**.

## What was updated

**The critical one.** A flaw in `node-tar` — a library used for reading compressed archives — where a deliberately malformed archive could consume unlimited memory and crash the process. Fixed by moving the build toolchain from `electron-builder` 24 to 26, the current latest, which carries a patched `node-tar` with it.

**Six smaller libraries**, updated in place: `js-yaml`, `@xmldom/xmldom`, `brace-expansion`, `tmp`, `form-data` and `@tootallnate/once`. Between them these covered denial-of-service flaws, a path-traversal issue, and a handful of parser bugs.

Three of those six — `js-yaml`, `brace-expansion` and `tmp` — genuinely ship inside the installed app rather than only being used to build it, so those are real fixes to code running on your machine. That was confirmed by reading the contents of the built application package directly, not assumed from a dependency list.

**No Anchor Hub code was changed.** The entire change is to the two files that record which library versions the app uses. The installer was then rebuilt and verified end to end before release.

## What was deliberately left alone

Two items were looked at and consciously not changed, which is worth recording honestly rather than leaving as a silent gap.

**Electron** — the framework Anchor Hub itself runs on — remains on version 28. It accounts for 32 of the remaining advisories, and unlike most of the above, those do reach your machine. The fix is version 44: sixteen major versions ahead. The blocker is `keytar`, the component that stores your saved credentials securely in Windows. It is a low-level module compiled specifically against the framework version, and it has not had a release since February 2022, so a build compatible with Electron 44 almost certainly does not exist. Moving forward likely means replacing the credential storage mechanism first. That is a project in its own right, with its own testing, rather than something to slip into a patch.

**`xlsx`** — the library used to read Excel workbooks — carries two advisories with **no fix available anywhere**. Its maintainers (SheetJS) withdrew the package from the public npm registry at version 0.18.5 and publish newer versions only from their own site. Every place Anchor Hub uses it is read-only, and only against internal workbooks from our own SharePoint rather than files from outside. The durable fix is to move those reads onto `exceljs`, which the app already uses for writing workbooks.

One change was explicitly **rejected**: the automated tooling offered to resolve a further advisory by downgrading `exceljs` from version 4 to version 3. That would have undone the fix that moved Anchor Hub onto `exceljs` in the first place — version 3 silently discards cell formatting, which is what broke the Puzzle payroll export previously — in exchange for closing an advisory that our code cannot actually reach.
